# 自带模型接入与资产管线

本文档说明外部 3D 模型的转换处理、ZMLBIKE1 自定义二进制格式契约、运行时 Mesh 生成及工业配色方案。

---

## 1. 模型资产来源与预处理

- **来源模型**：选用 Sidra 制作的 Low-Poly Motorcycle #2，遵循 CC BY 4.0 协议开源授权。
- **预处理转换工具**：使用基于开源库 `ufbx` 开发的转换工具 `tools/model-converter` 将原始 FBX 转换为轻量级二进制格式。
- **节点筛选与分件**：
  提取包含车体（Body）、转向叉（Steer）、单侧脚撑（Jack）、后轮（Wheel_B）及前轮（Wheel_F）在内的关键骨架分件。
  转换后保留 11 个材质分件、29,204 个顶点、23,016 个三角面，整车几何尺寸为长 2.2m、宽 0.83m、高 1.37m。

---

## 2. ZMLBIKE1 二进制格式契约

为了实现零第三方重型加载器依赖的高效加载，模型数据被压缩存储为小端序的 `ZMLBIKE1` 自定义二进制格式（总计约 489 KB）。

### 2.1 文件头结构
- **Magic**：`ZMLBIKE1`（8 字节 ASCII）；
- **PartCount**：分件数量（uint32，11 分件）。

### 2.2 分件头信息 (Part Header)
每个分件包含：
- **Role**：部件类型（0: 车身, 1: 后轮, 2: 前轮, 3: 转向架, 4: 支架）；
- **VertexCount / IndexCount**：顶点数与三角形索引数；
- **几何边界包围盒**：局部中心、Extent 与轴心坐标（Pivot）；
- **材质属性**：UV 缩放偏移与基础 RGBA 颜色标量。

### 2.3 顶点流定义 (Vertex Stride: 12 Bytes)
- **Position**：`int16 x 3`（经量化编码的局部空间三维坐标）；
- **OctNormal**：`uint8 x 2`（八面体八叉树压缩法线）；
- **UV**：`uint16 x 2`（量化纹理坐标）；
- **Indices**：`uint16` 索引数组。

## 3. 运行时加载与 Unity 渲染集成

### 3.1 动态 Mesh 构建
- 运行时在游戏主线程解析二进制数据流，通过 Unity 的原生数组构建每个部件的 `UnityEngine.Mesh`。
- 填充顶点、法线、切线、UV 与三角形拓扑，并调用 `Mesh.UploadMeshData(false)` 提交至 GPU。

### 3.2 材质与着色器模板
- 通过 `LuaResourceLoader` 借用游戏原生 `HGRP/Lit` 着色器作为模板。
- 为克隆的材质绑定专用调色板，并配置相应的延迟渲染（Deferred / GBuffer）管线参数。

### 3.3 轴心校准与中立几何
- 原模型的前叉与轮胎存在初始烘焙姿态偏差，转换管线通过 `calibrate-bike.py` 进行轴心扶正与几何校准，使车轮能够精确绕中心转动、车把能够绕前倾轴真实旋转。

---

## 4. 配色方案

- 运行时采用白黄工业配色：白色烤漆主车身、鲜黄亮色车架结构、深灰机械零件与橡胶轮胎。
- 调色板在运行时由统一着色脚本处理，无需外挂重型高分辨率贴图文件。
